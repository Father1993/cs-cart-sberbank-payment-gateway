Для настройки онлайн-оплаты через API Сбербанка с передачей данных корзины в АТОЛ (с учетом того, что АТОЛ уже подключен в личном кабинете), вам необходимо выполнить интеграцию на стороне бэкенда и фронтенда.  
Ниже представлена детальная инструкция, основанная на предоставленных материалах.

### 1\. Подготовка и аутентификация

Для работы с «новым» шлюзом (ecommerce.sberbank.ru) вам потребуются учетные данные (логин и пароль мерчанта), которые используются для аутентификации в каждом API-запросе 1, 2\.  
**Важный нюанс (Сертификаты):** Из-за санкционных ограничений Сбербанк использует сертификаты НУЦ Минцифры. Для корректного взаимодействия вашего сервера со шлюзом необходимо установить эти сертификаты на бэкенд (особенно если сервис работает в Docker-контейнере) 3, 4\.

### 2\. Регистрация заказа через REST API (Бэкенд)

Первым шагом является отправка запроса на регистрацию заказа. В ответ шлюз пришлет orderId (идентификатор заказа) и formUrl (ссылку на платежную страницу) 5, 6\.  
**Обязательные параметры запроса:**

* userName и password — ваши учетные данные 1\.  
* orderNumber — уникальный номер заказа в вашей системе 1\.  
* amount — сумма в копейках (например, 10000 для 100 рублей) 1\.  
* returnUrl — адрес, куда вернется клиент после оплаты 1\.

**Передача корзины для АТОЛ (Параметр orderBundle):**Для того чтобы АТОЛ сформировал чек, в запросе на регистрацию заказа необходимо передать параметр orderBundle 7, 8\. Этот параметр содержит детализацию корзины:

* Наименования товаров.  
* Цену за единицу.  
* Количество.  
* Ставку НДС.  
* Контактные данные покупателя (email или phone) для отправки электронного чека 9\.

**Нюанс:** Дополнительные поля (такие как email, phone или специфические параметры фискализации) часто требуют активации через службу техподдержки Сбера (support\_ecomm@sberbank.ru), так как по умолчанию в личном кабинете они могут быть неактивны 10-12.

### 3\. Интеграция платежной формы (Фронтенд)

После получения orderId (на новом шлюзе он также называется bankInvoiceId), вы можете использовать **SberPay SDK Web** для отображения виджета оплаты.

1. **Установка SDK:** Можно установить через npm (указав путь к .tgz файлу) или подключить через UMD-сборку (index.umd.cjs) 13, 14\.  
2. **Инициализация:** Создайте экземпляр виджета для среды PRODUCTION 15\.  
3. **Открытие виджета:** Вызовите метод open, передав bankInvoiceId и backUrl 16, 17\.  
4. const widgetParams \= {  
5.   bankInvoiceId: 'ваш\_orderId\_из\_ответа\_API',  
6.   backUrl: 'https://your-site.com/success'  
7. };  
8. widget.open(widgetParams);

### 4\. Обработка результата и обратный вызов (Callback)

Чтобы ваша система узнала об успешной оплате и АТОЛ мог фискализировать чек, необходимо настроить обработку статуса.

* **Callback-уведомления:** Рекомендуется настроить уведомления с контрольной суммой через техподдержку 18, 19\. При получении уведомления от Сбера ваш сервер должен ответить кодом 200 18\.  
* **Проверка статуса:** Дополнительно к callback, настройте периодический опрос API (запрос «Статус заказа»), чтобы гарантированно обновить состояние оплаты, если уведомление задержалось 20-22.  
* **Фискализация:** В схеме с подключенным АТОЛ шлюз Сбербанка автоматически передает данные в ОФД после успешной транзакции, если вы корректно передали корзину в параметре orderBundle 7-9.

### Основные особенности и нюансы:

1. **Срок жизни заказа:** Вы можете ограничить время на оплату через параметр sessionTimeoutSecs (в секундах) или expirationDate, чтобы заказ не «висел» бесконечно 23, 24\.  
2. **Тестирование:** На тестовом контуре Сбербанка также требуются сертификаты Минцифры для корректной работы 25\.  
3. **Логирование:** Рекомендуется сохранять полные JSON-ответы от шлюза в базу данных (например, MongoDB) для возможности разбора спорных ситуаций с техподдержкой 26, 27\.  
4. **Альтернативные домены:** Для того чтобы клиенты не видели предупреждений о «небезопасном соединении» (из-за сертификатов), попросите поддержку подключить «альтернативные домены» платежных страниц, сертифицированные Let’s Encrypt 3, 4\.

**Важно:** Поскольку в предоставленных источниках нет полной JSON-схемы параметра orderBundle (структуры массива товаров), я рекомендую запросить актуальную спецификацию REST API именно для вашей версии АТОЛ в поддержке Сбербанка, так как структура чека должна строго соответствовать формату ФФД 1.2 28\.
