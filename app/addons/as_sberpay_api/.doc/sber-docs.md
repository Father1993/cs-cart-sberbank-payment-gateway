# Документация API Сбербанка — Платёжный шлюз (REST API)

> **Цель документа**: Поддержка разработки модуля оплаты для CS-Cart 4.18+ через REST API Сбербанка (без SDK).  
> **Для AI-агентов**: Документ структурирован для быстрого извлечения контекста. Используйте разделы `##` для навигации.  
> **⚠️ ВАЖНО**: Используйте только **новый API** (прямой протокол). Старый API описан для справки, но **НЕ ИСПОЛЬЗУЕТСЯ**.

## 2. Два варианта API (важно различать)

### 2.1 ✅ Новый API (Прямой протокол / Платёжный шлюз партнёра) — ИСПОЛЬЗОВАТЬ

> **⚠️ КРИТИЧЕСКИ ВАЖНО**: Модуль `as_sberpay_api` использует **ТОЛЬКО новый API**. Все запросы должны идти на новые адреса.

| Параметр         | Значение                                                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Тест**         | `https://ecomtest.sberbank.ru/ecomm/gw/partner/api/v1/`                                                                                                         |
| **Тест IP**      | `194.54.15.41`                                                                                                                                    |
| **Продакшн**     | `https://epay.sberbank.ru/ecomm/gw/partner/api/v1/`                                                                                                             |
| **Content-Type** | `application/json`                                                                                                                                              |
| **Метод**        | `POST` (только POST, GET не поддерживается)                                                                                                                      |
| **Методы**       | `register.do`, `registerPreAuth.do`, `deposit.do`, `reverse.do`, `refund.do`, `getOrderStatusExtended.do`, `decline.do`, `paymentOrder.do`, `paymentSberPay.do` |

**Ограничения протокола:**
1. Поддерживается только HTTP POST метод (HTTP GET не поддерживается)
2. Параметры запроса передаются только в теле JSON-сообщений (`Content-Type: application/json`)
3. Не поддерживается SOAP интерфейс
4. Используется более строгая пре-валидация запросов согласно схемам
5. Состав и логика обработки максимально приближены к предыдущему решению, исключения могут составлять собственные сервисы для 3DS 2.0

**Рекомендации:**
- При регистрации заказа всегда указывать `features` (`FORCE_SSL`/`FORCE_FULL_TDS`) для стабильности работы запросов при изменении бэкового функционала и строгого маркирования операций по типу SSL/3DS.

### 2.2 ❌ Старый API (RBS / payment/rest) — НЕ ИСПОЛЬЗОВАТЬ

> **⚠️ ВНИМАНИЕ**: Это устаревший API. Информация приведена только для справки. **НЕ ИСПОЛЬЗУЙТЕ** эти адреса в новом коде.

| Параметр         | Значение                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| **Тест**         | `https://3dsec.sberbank.ru/payment/rest/` — ❌ НЕ ИСПОЛЬЗОВАТЬ                                                              |
| **Продакшн**     | `https://securepayments.sberbank.ru/payment/rest/` — ❌ НЕ ИСПОЛЬЗОВАТЬ                                                        |
| **Content-Type** | `application/x-www-form-urlencoded`                                                                       |
| **Методы**       | `register.do`, `registerPreAuth.do`, `deposit.do`, `reverse.do`, `refund.do`, `getOrderStatusExtended.do` |

**Почему не использовать:**
- Устаревший формат (form-urlencoded вместо JSON)
- Меньшая техническая конверсия
- Низкий приоритет поддержки
- Отсутствие новых функций (3DS 2.0, SberPay и др.)

## 5. Методы API (новый API, JSON)

### 5.1 Регистрация заказа — `register.do` (одностадийный)

**Endpoint:** `POST /ecomm/gw/partner/api/v1/register.do`

**Request (JSON):**

```json
{
    "userName": "sbertest_2221",
    "password": "Sbertest2026123456",
    "orderNumber": "e2574f1785324f1592d9029cb05adbbd",
    "amount": 19900,
    "returnUrl": "https://testmerchant.ru/return",
    "failUrl": "https://testmerchant.ru/fail",
    "features": "FORCE_SSL"
}
```

**Обязательные параметры:**

| Параметр      | Тип               | Описание                                                     |
| ------------- | ----------------- | ------------------------------------------------------------ |
| `userName`    | string [1..30]    | Логин партнёра (для прямого протокола — без суффикса `-api`) |
| `password`    | string [1..36]    | Пароль партнёра                                              |
| `orderNumber` | string [1..36]    | Уникальный номер заказа в системе мерчанта                   |
| `amount`      | integer           | Сумма в копейках (минимальных единицах валюты)               |
| `returnUrl`   | string [12..2048] | URL успешного возврата (https)                               |

**Опциональные параметры:**

| Параметр             | Тип                | По умолчанию | Описание                                                                             |
| -------------------- | ------------------ | ------------ | ------------------------------------------------------------------------------------ |
| `currency`           | string (3 цифры)   | "643"        | Код валюты ISO-4217                                                                  |
| `failUrl`            | string             | = returnUrl  | URL при ошибке оплаты                                                                |
| `description`        | string [1..512]    | —            | Описание заказа                                                                      |
| `language`           | string (2 символа) | "ru"         | Язык (ISO 639-1)                                                                     |
| `clientId`           | string             | —            | ID плательщика (для связок)                                                          |
| `sessionTimeoutSecs` | integer            | 1200         | Время жизни заказа (сек)                                                             |
| `phone`              | string             | —            | Телефон плательщика (+79998887700)                                                   |
| `email`              | string             | —            | Email плательщика                                                                    |
| `dynamicCallbackUrl` | string (https)     | —            | URL для callback-уведомлений                                                         |
| `features`           | string             | —            | См. таблицу ниже                                                                     |
| `jsonParams`         | object             | —            | Доп. параметры. **Для SberPay обязателен** `sberbankOnlineAttributes` (см. раздел 6) |

**Параметр `features` (через `;`):**

| Значение         | Описание                                                 |
| ---------------- | -------------------------------------------------------- |
| `VERIFY`         | Верификация без списания                                 |
| `AUTO_PAYMENT`   | Оплата по сохранённой карте (связка)                     |
| `FORCE_SSL`      | Без 3-D Secure (высокорисковый, подключается по запросу) |
| `FORCE_TDS`      | Обязательно с 3-D Secure                                 |
| `FORCE_FULL_TDS` | Только успешная 3DS аутентификация (Y)                   |

**Response (успех):**

```json
{
    "errorCode": "0",
    "errorMessage": "Обработка запроса прошла без системных ошибок",
    "orderId": "a67b0ced-c9a4-4cfb-bce3-b9595afaafc1",
    "formUrl": "https://ecomtest.sberbank.ru/pp/pay_ru?orderId=a67b0ced-c9a4-4cfb-bce3-b9595afaafc1",
    "externalParams": {
        "sbolDeepLink": "sberpay://invoicing/v2?bankInvoiceId=a67b0cedc9a44cfbbce3b9595afaafc1&operationType=Web2App&option=Connect"
    }
}
```

**Response (ошибка):**

```json
{
    "errorCode": "1",
    "errorMessage": "Заказ с таким номером уже обработан"
}
```

**Важно для orderNumber:**

- Должен быть уникальным в рамках шлюза.
- Ошибка `"Заказ с таким номером уже обработан"` — используйте новый `orderNumber` при повторной попытке (например, `{order_id}_{hash}`).
- **Рекомендуемый формат для CS-Cart:** `{order_id}_{substr(md5(order_id + timestamp), 0, 3)}`

## 6. SberPay — Web2App (нативная интеграция без SDK)

**При работе с SberPay использование блока `sberbankOnlineAttributes` в `jsonParams` при регистрации заказа (register/registerPreAuth) является обязательным.**

### 6.1 Два сценария Web2App (без SDK)

| Сценарий                      | Описание                                                                                                       | UX                                            |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| **QR-код**                    | Партнёр выводит QR на странице. Клиент сканирует → открывается Сбербанк-Онлайн → подтверждение оплаты.         | Показать QR из ответа (или URL для генерации) |
| **Оплата по номеру телефона** | Кнопка «Оплатить по номеру телефона». Клиент вводит телефон → PUSH/SMS → приложение Сбербанка → подтверждение. | Поле ввода телефона + кнопка                  |

### 6.2 Блок sberbankOnlineAttributes (обязательный)

```json
{
    "jsonParams": {
        "sberbankOnlineAttributes": {
            "language": "ru"
        }
    }
}
```

Дополнительные параметры — по документации Сбера. Без этого блока SberPay не будет работать.

### 6.3 Ответ register — externalParams для SberPay

```json
{
    "externalParams": {
        "sbolDeepLink": "sberpay://invoicing/v2?bankInvoiceId=...&operationType=Web2App&option=Connect"
    }
}
```

- **sbolDeepLink** — ссылка для открытия приложения Сбербанк-Онлайн (мобильный).
- **Платёжная страница** — альтернатива: если SberPay подключён на платежной странице Сбера, можно редиректить на `formUrl` — клиент увидит кнопку SberPay и QR на самой форме.

### 6.4 iOS: перебор диплинков

⚠️ **При нативной интеграции Web2App на устройствах Apple необходимо реализовать процедуру перебора диплинков** — разные версии приложения Сбербанка используют разные URL-схемы. Подробная инструкция в документации Сбера.

### 6.5 Поток оплаты (схема)

```
Плательщик                    Партнёр (CS-Cart)              Платёжный шлюз
    │                               │                              │
    │  Создание заказа              │                              │
    │  Выбор SberPay                │                              │
    │  ─────────────────────────────>                              │
    │                               │  Register / RegisterPreAuth   │
    │                               │  (jsonParams.sberbankOnlineAttributes) │
    │                               │  ─────────────────────────────>│
    │                               │  < orderId, formUrl, sbolDeepLink
    │                               │                              │
    │  QR или кнопка «По телефону»  │                              │
    │  <─────────────────────────────                              │
    │  Оплата в СБОЛ                │                              │
    │  ────────────────────────────────────────────────────────────>│
    │                               │  < Нотификация по статусу      │
    │                               │  getOrderStatusExtended        │
    │                               │  deposit (если PreAuth)        │
```

### 6.6 Три способа оплаты (сводка)

| Способ                 | Как инициировать                                                   | Куда ведёт клиента                    |
| ---------------------- | ------------------------------------------------------------------ | ------------------------------------- |
| **Карта**              | `register.do` → `formUrl`                                          | Платёжная страница Сбера (ввод карты) |
| **SberPay**            | `register.do` + `sberbankOnlineAttributes` → `sbolDeepLink` или QR | Приложение Сбербанк-Онлайн            |
| **Платёжная страница** | `formUrl` (если SberPay подключён на платежной странице)           | Страница Сбера с кнопкой SberPay + QR |

## 7. Callback и Return URL

| URL                  | Назначение                                                       |
| -------------------- | ---------------------------------------------------------------- |
| `returnUrl`          | GET, клиент возвращается после успешной оплаты                   |
| `failUrl`            | GET, клиент возвращается при ошибке                              |
| `dynamicCallbackUrl` | POST, серверное уведомление о статусе (основной источник истины) |

**Важно:**

- Callback может прийти раньше Return.
- Callback может вызываться несколько раз — нужна идемпотентность (проверка статуса заказа).
- Домены с кириллицей — преобразовать в ACE (Punycode). Пример: `сберпей.рф` → `xn--90aiaq2afe.xn--p1ai`.

## 8. Фискализация (54-ФЗ)

### 8.1 Условия формирования чеков

Для успешной регистрации кассового чека необходимо:

1. **Передать корзину** с обязательными параметрами `ffdVersion` и `receiptType` в любом из сервисов: `register`, `registerPreAuth`, `deposit`, `reverse`, `refund`.
2. **Подключить кассу** в настройках мерчанта (логин СберБизнес или запрос в ТП).

### 8.2 Поддерживаемые кассы

| Касса                     | ФФД       | Примечание                                              |
| ------------------------- | --------- | ------------------------------------------------------- |
| **АТОЛ Онлайн**           | 1.05, 1.2 | Регистрация в АТОЛ Онлайн → учётные данные в СберБизнес |
| **Цифровая касса Эвотор** | 1.05, 1.2 | Регистрация в Цифровая касса для облачной кассы         |
| **Бизнес.ру**             | 1.05, 1.2 | Запрос в поддержку Бизнес.Ру на интеграцию api-sberbank |
| **OFD.RU**                | 1.1, 1.2  | Личный кабинет Партнёр OFD.RU                           |

### 8.3 Доступный функционал фискализации

- Отправка данных в онлайн-кассу (ФФД 1.05 и 1.2)
- Чеки прихода, возврата прихода (в т.ч. частичного)
- Переотправка неуспешного чека с изменением корзины
- Переотправка при ошибке кассы или таймауте
- Закрывающий чек (отдельно от финансовой операции)
- Разделение чека при превышении размера
- Получение статуса чека отдельным API-запросом

### 8.4 orderBundle — структура корзины

Блок передаётся в `register.do` / `registerPreAuth.do` и т.д. Цепочка: **CS-Cart → Сбер → АТОЛ → ФНС**.

**Обязательные поля в корзине:** `ffdVersion`, `receiptType` (в составе orderBundle или на уровне запроса — по документации).

```json
{
    "ffdVersion": "1.05",
    "receiptType": "income",
    "taxSystem": 0,
    "orderBundle": {
        "orderCreationDate": 1700000000,
        "customerDetails": {
            "email": "test@test.ru",
            "phone": "+79001234567"
        },
        "cartItems": {
            "items": [
                {
                    "positionId": 1,
                    "name": "Товар 1",
                    "quantity": { "value": 2, "measure": "шт" },
                    "itemAmount": 20000,
                    "itemCode": "SKU001.1",
                    "itemPrice": 10000,
                    "tax": { "taxType": 6 },
                    "itemAttributes": {
                        "attributes": [
                            { "name": "paymentMethod", "value": 1 },
                            { "name": "paymentObject", "value": 1 }
                        ]
                    }
                }
            ]
        }
    }
}
```

**Справочники:**

- **taxType**: 0 — без НДС, 1 — 0%, 2 — 10%, 6 — 20%, 10 — 5%, 12 — 7%
- **taxSystem**: 0 — общая, 1 — УСН доход, 2 — УСН доход-расход, 3 — ЕНВД, 4 — ЕСХН, 5 — патент
- **paymentMethod**: 1 — полная предоплата, 4 — полная оплата, и др.
- **paymentObject**: 1 — товар, 4 — услуга, и др.
- **ffdVersion**: `1.05` или `1.2` (в запросе передавать как строку)
- **receiptType**: тип чека (приход, возврат и т.д.) — по документации 54-ФЗ

### 8.5 Подключение кассы АТОЛ

1. Зарегистрироваться в сервисе «АТОЛ Онлайн».
2. Зарегистрировать кассу в ФНС и у ОФД.
3. Получить учётные данные в ЛК АТОЛ (логин, пароль, код группы ККТ).
4. Настроить интеграцию через СберБизнес или запрос в ТП интернет-эквайринга Сбербанка (указать учётные данные и версию ФФД).

## 10. Маппинг для CS-Cart 4.18+

| CS-Cart                          | Сбербанк                                      |
| -------------------------------- | --------------------------------------------- |
| `order_id`                       | `orderNumber` (формат: `{order_id}_{hash}`)   |
| `transaction_id`                 | `orderId` (UUID из ответа register)           |
| Статус P (Paid)                  | `orderStatus = 2`                             |
| Статус F (Failed)                | `orderStatus = 3, 6` или ошибка               |
| `fn_finish_payment()`            | После проверки через `getOrderStatusExtended` |
| `fn_update_order_payment_info()` | Сохранение `orderId` как `transaction_id`     |

**Рекомендуемый orderNumber:** `{order_id}_{substr(md5(order_id + timestamp), 0, 3)}` — для уникальности при повторных попытках.
