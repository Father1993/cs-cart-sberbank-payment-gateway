# Настройки модуля — AS SberPay API

## Где настраивать

Админка → Администрирование → Способы оплаты → [Выбрать SberPay API] → Настроить

---

## Основные настройки

### Логин (login)

- API логин от Сбербанка
- Формат зависит от договора: `P1234567890` или `P1234567890-api`
- Получается при регистрации в системе интернет-эквайринга
- **Если Access denied** — уточнить формат логина в поддержке Сбера

### Пароль (password)

- Пароль от API
- Требования: минимум 18 символов, 1 цифра, 1 заглавная латинская буква
- Смена через: https://ecomtest.sberbank.ru/doc#tag/changePasswordServices

### Режим (mode)

| Значение | Платёжный API                                               | OFD API                                                         |
|----------|-------------------------------------------------------------|-----------------------------------------------------------------|
| test     | `https://ecomtest.sberbank.ru/ecomm/gw/partner/api/v1/`     | `https://ecomtest.sberbank.ru/ecomm/gw/partner/api/ofd/v1/`     |
| live     | `https://epay.sberbank.ru/ecomm/gw/partner/api/v1/`         | `https://epay.sberbank.ru/ecomm/gw/partner/api/ofd/v1/`         |

- Начинать всегда с `test`
- Переключать на `live` только после успешного тестирования

### Стадийность (two_staging)

| Значение       | API метод            | Поведение                           |
|----------------|----------------------|-------------------------------------|
| Одностадийные  | `register.do`        | Деньги списываются сразу            |
| Двустадийные   | `registerPreAuth.do` | Сначала холд, потом deposit/reverse |

- Для большинства магазинов подходят **одностадийные**

### Статус при успешной оплате (confirmed_order_status)

- Какой статус получит заказ после подтверждения оплаты
- По умолчанию: P (Оплачен)

### Логирование (logging)

- Включает запись всех запросов/ответов в файл
- Путь: `var/logs/as_sberpay_api/sberpay_YYYY-MM.log`
- **Рекомендуется включить при настройке и отладке**

## Фискализация (54-ФЗ)

### Отправлять корзину на шлюз (send_order)

- Включает передачу `orderBundle` в запросе `register.do`
- **Обязательно для формирования чеков через АТОЛ**
- Также включает отправку закрывающего чека `doReceipt` через OFD endpoint при переводе заказа в «Выполнен»

### Система налогообложения (tax_system)

| Код | Система                        |
|-----|--------------------------------|
| 0   | Общая (ОСН)                    |
| 1   | Упрощённая, доход (УСН)        |
| 2   | Упрощённая, доход минус расход |
| 3   | ЕНВД                           |
| 4   | ЕСХН                           |
| 5   | Патент                         |

### Ставка НДС по умолчанию (tax_type)

Применяется ко всем позициям в чеке.

| Код | Ставка      |
|-----|-------------|
| 0   | Без НДС     |
| 1   | НДС 0%      |
| 2   | НДС 10%     |
| 4   | НДС 10/110  |
| 6   | НДС 20%     |
| 7   | НДС 20/120  |
| 8   | НДС 5%      |
| 9   | НДС 5/105   |
| 10  | НДС 7%      |
| 11  | НДС 7/107   |
| 12  | НДС 22% ← **по умолчанию** |
| 13  | НДС 22/122  |

### Версия ФФД (ffd_version)

| Версия | measurementUnit    | ffdVersion в API |
|--------|--------------------|------------------|
| 1.05   | Текст: `"шт."`     | `"1.05"`         |
| 1.2    | Код: `0`           | `"1.2"`          |

Уточнить у АТОЛ / в ЛК Сбера какая версия используется.

### Признак способа расчёта (payment_method)

Передаётся в `paymentMethod` каждой позиции чека (Тэг ФФД 1214).

| Значение          | Описание                        |
|-------------------|---------------------------------|
| `full_prepayment` | Полная предоплата ← **по умолчанию** |
| `prepayment`      | Частичная предоплата            |
| `advance`         | Аванс                           |
| `full_payment`    | Полный расчёт                   |

> Для интернет-магазина с предоплатой — `full_prepayment`.
> Закрывающий чек при выдаче товара всегда отправляется с `full_payment` автоматически.

## Частые проблемы

### Access denied (errorCode: 5)

1. Уточнить правильный формат логина у Сбера
2. Проверить что используется правильный режим (test/live)
3. Проверить пароль (18+ символов, 1 цифра, 1 заглавная)
4. Написать в поддержку Сбера: support_ecomm@sberbank.ru

> В новом Partner API `errorCode: 5` означает «Ошибка значения параметра», а не «Access denied» как в старом RBS.

### Заказ с таким номером уже обработан (errorCode: 1)

- Нормально при повторной попытке оплаты того же заказа
- Модуль добавляет hash к orderNumber для уникальности

### Чек не формируется

1. Включить "Отправлять корзину на шлюз"
2. Проверить что АТОЛ подключён в ЛК Сбера
3. Убедиться что аккаунт боевой (на тестовом аккаунте `sbertest_2221` фискализация не работает)
4. Проверить систему налогообложения
5. Проверить версию ФФД

### Закрывающий чек не отправляется

Проверить что одновременно выполняются все условия:
1. Включена опция "Отправлять корзину на шлюз"
2. Заказ был оплачен через SberPay API (есть transaction_id)
3. Способ оплаты заказа использует процессор `as_sberpay_api.php`
4. Статус меняется именно на `C` (Выполнен)
5. Для закрывающего чека используется OFD endpoint `doReceipt` через `/partner/api/ofd/v1/`
