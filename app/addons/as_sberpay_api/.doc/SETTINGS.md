# Настройки модуля — AS SberPay API

## Где настраивать

Админка → Администрирование → Способы оплаты → [Выбрать SberPay API] → Настроить

---

## Основные настройки

### Логин (login)

- API логин от Сбербанка
- Обычно вида `P1234567890-api` (с суффиксом `-api`)
- Получается при регистрации в системе эквайринга
- **Если Access denied** — проверь суффикс `-api`

### Пароль (password)

- Пароль от API
- Требования: 1 цифра, 1 заглавная латинская, минимум 18 символов
- Смена через: https://ecomtest.sberbank.ru/doc#tag/changePasswordServices
- Или через ЛК Сбербизнес: https://www.sberbank.ru/help/business/sbbol/100667

### Режим (mode)

| Значение | URL API                                              |
|----------|------------------------------------------------------|
| test     | `https://3dsec.sberbank.ru/payment/rest/`            |
| live     | `https://securepayments.sberbank.ru/payment/rest/`   |

- Начинать всегда с `test`
- Переключать на `live` только после успешного тестирования

### Стадийность (two_staging)

| Значение       | API метод            | Поведение                          |
|----------------|----------------------|------------------------------------|
| Одностадийные  | `register.do`        | Деньги списываются сразу           |
| Двустадийные   | `registerPreAuth.do` | Сначала холд, потом deposit/reverse|

- Для большинства магазинов подходят **одностадийные**
- Двустадийные нужны если требуется подтверждение перед списанием

### Статус при успешной оплате (confirmed_order_status)

- Какой статус получит заказ после оплаты
- По умолчанию: P (Processed / Обработан)
- Можно выбрать любой статус из списка

### Логирование (logging)

- Включает запись всех запросов/ответов в файл
- Путь: `var/logs/as_sberpay_api/sberpay_YYYY-MM.log`
- **Рекомендуется включить при настройке и отладке**
- В продакшене можно выключить для экономии места

## Фискализация (54-ФЗ)

Раздел появляется в настройках оплаты.

### Отправлять корзину на шлюз (send_order)

- Включает передачу `orderBundle` в запросе `register.do`
- **Обязательно для формирования чеков через АТОЛ**
- Если АТОЛ подключён через Сбер — включить обязательно
- Если АТОЛ не подключён — можно не включать

### Система налогообложения (tax_system)

| Код | Система                          |
|-----|----------------------------------|
| 0   | Общая (ОСН)                      |
| 1   | Упрощённая, доход (УСН)          |
| 2   | Упрощённая, доход минус расход   |
| 3   | ЕНВД                             |
| 4   | ЕСХН                             |
| 5   | Патент                           |

Выбирать в соответствии с вашей налоговой системой.

### Ставка НДС по умолчанию (tax_type)

| Код | Ставка     |
|-----|------------|
| 0   | Без НДС    |
| 1   | НДС 0%     |
| 2   | НДС 10%    |
| 6   | НДС 20%    |
| 10  | НДС 5%     |
| 12  | НДС 7%     |

Применяется ко всем позициям в чеке.

### Версия ФФД (ffd_version)

| Версия | measure в quantity         |
|--------|----------------------------|
| 1.05   | Текст: `шт`               |
| 1.2    | Код: `0`                   |

Уточнить у АТОЛ / в ЛК Сбера какая версия используется.

### Тип оплаты (payment_method_type)

- По умолчанию: 1 (Полная предоплата)
- Для большинства интернет-магазинов = 1

### Тип предмета расчёта (payment_object_type)

- По умолчанию: 1 (Товар)
- Для доставки и наценок автоматически ставится 4 (Услуга)

## Частые проблемы

### Access denied

1. Проверить суффикс `-api` в логине
2. Проверить URL (test/live не перепутаны?)
3. Проверить пароль (18+ символов, 1 цифра, 1 заглавная)
4. Проверить доступ с сервера: `curl https://3dsec.sberbank.ru`
5. Написать в поддержку Сбера: support_ecomm@sberbank.ru

### Заказ с таким номером уже обработан (errorCode=1)

- Нормально при повторной попытке оплаты того же заказа
- Модуль добавляет hash к orderNumber для уникальности

### Чек не формируется

1. Включить "Отправлять корзину на шлюз"
2. Проверить что АТОЛ подключён в ЛК Сбера
3. Проверить систему налогообложения
4. Проверить версию ФФД
