    🔑 Ключевые компоненты

    1. AsSberPayApi.php — ядро процессора

    Основные методы:


    ┌──────────────────────────┬───────────────────────────────────────────────────────┐
    │ Метод                    │ Назначение                                            │
    ├──────────────────────────┼───────────────────────────────────────────────────────┤
    │ register()               │ Регистрация заказа (register.do / registerPreAuth.do) │
    │ getOrderStatusExtended() │ Проверка статуса заказа                               │
    │ refund()                 │ Возврат средств (refund.do)                           │
    │ reverse()                │ Отмена заказа (reverse.do)                            │
    │ deposit()                │ Завершение двустадийного платежа (deposit.do)         │
    │ buildOrderBundle()       │ Формирование фискальных данных (54-ФЗ → АТОЛ)         │
    └──────────────────────────┴───────────────────────────────────────────────────────┘


    Критичные особенности:
     - Использует application/json (НЕ form-urlencoded)
     - Авторизация через userName + password в теле запроса
     - Поддерживает фискализацию через orderBundle → Сбер → АТОЛ → ФНС

    2. payments/as_sberpay_api.php — обработчик платежей

    3 потока обработки:

     1. Callback (action=callback) — серверное уведомление от Сбера (приоритетное)
     2. Return (action=return) — клиент вернулся после оплаты
     3. Register (иначе) — инициация платежа, редирект на форму Сбера

    Защита:
     - Проверка transaction_id
     - Идемпотентность (не обрабатывает повторно оплаченный заказ)

    ---

    🔄 Потоки оплаты

    Одностадийный платёж (основной)

     1 CS-Cart → register.do → formUrl → Клиент оплачивает →
     2 Callback/Return → getOrderStatusExtended → fn_finish_payment()

    Двустадийный платёж

     1 registerPreAuth.do → Холд → deposit.do → Списаниe
     2                          ↓
     3                     reverse.do → Отмена

    Фискализация (54-ФЗ)

     1 CS-Cart → orderBundle → Сбер → АТОЛ Онлайн → ФНС

    📝 История изменений (из CONTEXT.md)

    Итерация 4 (2026-03-03) — Исправление errorCode: 5

    Диагноз: Тестовый аккаунт не поддерживает фискальные параметры

    Решения:
     1. sberbankOnlineAttributes → json_encode() (строка, НЕ объект)
     2. Фискальные параметры работают только на боевом аккаунте с АТОЛ
     3. Добавлен features: 'FORCE_FULL_TDS'
     4. itemAttributes.value → тип string

    ⚠️ Известные ограничения

     1. Тестовый аккаунт (sbertest_2221) не поддерживает АТОЛ — любые фискальные параметры вызывают errorCode: 5
