## Описание проекта

Модуль интернет-эквайринга Сбербанка для CMS CS-Cart 4.18 Multivendor через **новый партнёрский REST API** (application/json).

**Репозиторий:** `D:\OS\home\uroven.local\repo\cs-cart-as_sberpay_api\`

### 2. API Сбербанка

| Метод API                   | Статус | Описание                                      |
| --------------------------- | ------ | --------------------------------------------- |
| `register.do`               | ✅     | Регистрация заказа (одностадийный)            |
| `registerPreAuth.do`        | ✅     | Регистрация с предавторизацией (двустадийный) |
| `getOrderStatusExtended.do` | ✅     | Проверка статуса заказа                       |
| `refund.do`                 | ✅     | Возврат средств                               |
| `reverse.do`                | ✅     | Отмена заказа                                 |
| `deposit.do`                | ✅     | Завершение двустадийного платежа              |
| `doReceipt.do`              | ✅     | Закрывающий чек (54-ФЗ, при выдаче товара)    |

**URL API:**

- Тест: `https://ecomtest.sberbank.ru/ecomm/gw/partner/api/v1/`
- Прод: `https://epay.sberbank.ru/ecomm/gw/partner/api/v1/`

**Формат запросов:** `application/json` (НЕ form-urlencoded)

---

### 3. Платёжные сценарии

| Сценарий                        | Статус      | Описание                                               |
| ------------------------------- | ----------- | ------------------------------------------------------ |
| **Оплата картой**               | ✅          | `register.do` → `formUrl` → редирект на страницу Сбера |
| **SberPay (через форму Сбера)** | ⚠️ Частично | Клиент видит кнопку SberPay на странице Сбера          |
| **SberPay (нативно)**           | ❌          | QR-код, deeplink — не реализовано                      |
| **СБП**                         | ❌          | Полностью отсутствует                                  |

---

### 4. Обработчики платежей

| Обработчик                       | Статус | Описание                                       |
| -------------------------------- | ------ | ---------------------------------------------- |
| **CALLBACK** (`action=callback`) | ✅     | Серверное уведомление от Сбера                 |
| **RETURN** (`action=return`)     | ✅     | Клиент вернулся после оплаты                   |
| **ERROR** (`mode=error`)         | ✅     | Клиент вернулся после ошибки                   |
| **REGISTER** (инициация)         | ✅     | Создание заказа в Сбере, редирект на `formUrl` |

---

### 5. Фискализация (54-ФЗ)

| Функция             | Статус | Описание                                                                           |
| ------------------- | ------ | ---------------------------------------------------------------------------------- |
| `orderBundle`       | ✅     | Формирование корзины для АТОЛ                                                      |
| `taxSystem`         | ✅     | Система налогообложения (0-5)                                                      |
| `taxType`           | ✅     | Ставка НДС — константы `TAX_*`, коды 0,1,2,4,6,7,8,9,10,11,12,13                   |
| `ffdVersion`        | ✅     | Версия ФФД (1.05 / 1.2)                                                            |
| `paymentMethod`     | ✅     | Признак способа расчёта — константы `PM_*` (строки: `full_prepayment` и др.)       |
| `paymentObject`     | ✅     | Признак предмета расчёта — константы `PO_*` (строки: `commodity`, `service` и др.) |
| `receiptType`       | ✅     | Тип чека (`SELL`)                                                                  |
| `company`           | ✅     | Реквизиты продавца в чеке                                                          |
| **Закрывающий чек** | ✅     | `doReceipt.do` при переводе заказа в «Выполнен» (C)                                |

**Важно:** Фискализация работает только на боевом аккаунте с подключённой кассой (АТОЛ). На тестовом `sbertest_2221` — не работает.

## Известные ограничения

1. **Callback не работает на локальном контуре** (`uroven.local`) — нужен публичный URL
2. **Фискализация не работает на тестовом аккаунте** `sbertest_2221` — любые фискальные параметры вызывают `errorCode: 5`; тестировать только на боевом `P272606974206`
3. **SberPay нативно не реализован** — клиент видит кнопку SberPay только на странице Сбера
4. **СБП полностью отсутствует**
